# 内容推荐与混合推荐

> 协同过滤只看用户行为，不关心物品本身是什么。内容推荐则相反——它分析物品的内容特征来做推荐。混合推荐把两者结合，取长补短。

## 📖 基于内容的推荐（Content-Based）

### 核心思想

```
"你喜欢科幻电影 → 推荐更多科幻电影"
"你常读 Python 文章 → 推荐更多 Python 文章"

不需要其他用户的数据，只需要:
  1. 用户的历史偏好
  2. 物品的内容特征
```

### 工作流程

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│ 物品内容分析  │     │ 用户画像构建  │     │ 匹配与推荐   │
│              │     │              │     │              │
│ 提取物品特征  │     │ 根据历史行为  │     │ 计算物品特征  │
│ 标签/类别/   │ ──→ │ 构建用户兴趣  │ ──→ │ 与用户画像的  │
│ 关键词/向量  │     │ 画像         │     │ 相似度       │
└──────────────┘     └──────────────┘     └──────────────┘
```

### 物品特征提取

以电影推荐为例：

```
电影《星际穿越》的特征:
  ┌─────────────────────────────────┐
  │ 类型:    [科幻, 冒险, 剧情]     │
  │ 导演:    克里斯托弗·诺兰        │
  │ 演员:    马修·麦康纳, 安妮·海瑟薇│
  │ 标签:    太空, 时间旅行, 亲情    │
  │ 年份:    2014                   │
  │ 评分:    9.4                    │
  │ 关键词:  黑洞, 虫洞, 五维空间    │
  └─────────────────────────────────┘

特征向量化 (One-Hot / Multi-Hot):
  类型: [1,0,0,1,1,0,0,0]  (科幻=1, 冒险=1, 剧情=1, 其他=0)
  导演: [0,0,1,0,0,...]    (诺兰=1)
```

### 文本内容的特征提取

对于新闻、文章等文本内容：

```
方法 1: TF-IDF
  TF (词频):  某词在文档中出现的频率
  IDF (逆文档频率): 某词在所有文档中的稀有程度
  TF-IDF = TF × IDF

  "Python" 在一篇编程文章中:
    TF = 出现 10 次 / 总词数 200 = 0.05
    IDF = log(总文档数 10000 / 包含"Python"的文档数 500) = 3.0
    TF-IDF = 0.05 × 3.0 = 0.15

方法 2: Embedding (现代方法)
  用预训练模型 (BERT, Sentence-BERT) 将文本转为向量
  "Python 入门教程" → [0.12, -0.34, 0.56, ..., 0.78]  (768维)
  语义相似的文本，向量距离更近
```

### 用户画像构建

```
Alice 的历史行为:
  看了《星际穿越》(科幻) → 评分 5
  看了《盗梦空间》(科幻) → 评分 5
  看了《泰坦尼克号》(爱情) → 评分 3
  看了《黑客帝国》(科幻) → 评分 4

Alice 的兴趣画像 (加权平均):
  科幻: (5+5+4)/3 = 4.67  ← 非常喜欢
  爱情: 3/1 = 3.0          ← 一般
  冒险: (5+4)/2 = 4.5      ← 喜欢
  
  → Alice 是科幻/冒险爱好者
```

### 推荐计算

```
候选电影《流浪地球》:
  特征: [科幻=1, 冒险=1, 剧情=1, 中国=1]

Alice 的兴趣向量:
  [科幻=4.67, 冒险=4.5, 剧情=3.2, 中国=?]

相似度 = cos(Alice兴趣, 流浪地球特征) = 很高

→ 推荐！
```

### Content-Based 的优缺点

```
✅ 优点:
  • 不需要其他用户数据 → 没有冷启动问题（对新用户）
  • 新物品只要有内容特征就能被推荐 → 解决物品冷启动
  • 可解释性强: "因为你喜欢科幻片，所以推荐这部"
  • 不受流行度偏差影响

❌ 缺点:
  • 过度专业化: 只推荐相似的，缺乏惊喜（信息茧房）
  • 特征工程依赖: 需要高质量的物品特征
  • 无法发现跨类别兴趣: 你喜欢科幻，但可能也会喜欢纪录片
  • 新用户仍需少量行为数据来构建画像
```

## 🧬 基于知识的推荐（Knowledge-Based）

适用于用户很少重复购买的场景（如房产、汽车）：

```
用户需求: "我想买一辆 20 万以内的 SUV，要省油"

知识库:
  ┌─────────────────────────────────────┐
  │ 车型        价格    类型   油耗     │
  │ 本田 CR-V   19.8万  SUV   6.4L    │ ← 匹配！
  │ 丰田 RAV4   18.5万  SUV   5.8L    │ ← 匹配！
  │ 宝马 X3     39.8万  SUV   8.1L    │ ← 超预算
  └─────────────────────────────────────┘

推荐: CR-V 和 RAV4
```

不依赖历史行为，而是基于用户明确表达的需求和物品的属性知识。

## 🔀 混合推荐（Hybrid Recommendation）

单一方法都有局限，混合推荐取长补短：

```
协同过滤:  擅长发现跨类别兴趣，但有冷启动问题
内容推荐:  没有冷启动问题，但容易过度专业化
混合推荐:  结合两者优势
```

### 混合策略

```
策略 1: 加权混合 (Weighted)
  ┌─────────────────────────────────────┐
  │ 最终分数 = α × CF分数 + β × CB分数  │
  │                                     │
  │ α, β 可以根据场景动态调整:           │
  │   新用户: α=0.2, β=0.8 (偏内容)     │
  │   老用户: α=0.8, β=0.2 (偏协同)     │
  └─────────────────────────────────────┘

策略 2: 切换混合 (Switching)
  ┌─────────────────────────────────────┐
  │ if 用户行为数据充足:                 │
  │     使用协同过滤                     │
  │ else:                               │
  │     使用内容推荐                     │
  └─────────────────────────────────────┘

策略 3: 级联混合 (Cascade)
  ┌─────────────────────────────────────┐
  │ 第一步: 内容推荐粗筛 → 候选集       │
  │ 第二步: 协同过滤精排 → 最终结果      │
  └─────────────────────────────────────┘

策略 4: 特征融合 (Feature Augmentation)
  ┌─────────────────────────────────────┐
  │ 将内容特征和协同特征拼接在一起       │
  │ 输入到统一的模型中学习               │
  │ → 这就是深度学习推荐的思路！         │
  └─────────────────────────────────────┘
```

### 工业界的实际做法

```
实际的推荐系统通常是多路召回 + 统一排序:

  召回阶段 (多路并行):
    ├── 协同过滤召回: 基于用户行为相似性
    ├── 内容召回: 基于物品内容相似性
    ├── 热门召回: 基于全局热度
    ├── 标签召回: 基于用户兴趣标签
    └── 向量召回: 基于 Embedding 相似性

  排序阶段 (统一模型):
    将所有召回结果送入一个排序模型
    模型同时使用协同特征和内容特征
    输出统一的排序分数

  → 这本质上就是一种混合推荐
```

## 📊 三种方法对比

```
┌──────────────┬──────────────┬──────────────┬──────────────┐
│              │ 协同过滤      │ 内容推荐      │ 混合推荐      │
├──────────────┼──────────────┼──────────────┼──────────────┤
│ 数据需求     │ 用户行为数据  │ 物品内容特征  │ 两者都需要    │
│ 冷启动       │ ❌ 严重       │ ✅ 较好       │ ✅ 较好       │
│ 多样性       │ ✅ 好         │ ❌ 差         │ ✅ 好         │
│ 可解释性     │ ⚠️ 一般       │ ✅ 好         │ ⚠️ 一般       │
│ 跨类别发现   │ ✅ 能         │ ❌ 不能       │ ✅ 能         │
│ 实现复杂度   │ 中等          │ 低            │ 高            │
│ 工业应用     │ 广泛          │ 辅助          │ 主流          │
└──────────────┴──────────────┴──────────────┴──────────────┘
```

## 🌍 实际案例

### YouTube 的推荐

```
YouTube 的推荐是典型的混合推荐:

  内容特征:
    - 视频标题、描述、标签
    - 视频画面内容 (CV 分析)
    - 音频内容 (ASR 转文字)
    - 频道信息

  协同信号:
    - 用户观看历史
    - 点赞/不喜欢
    - 评论
    - 分享

  上下文:
    - 时间 (工作日 vs 周末)
    - 设备 (手机 vs 电视)
    - 地理位置

  → 所有特征融合到深度学习模型中统一排序
```

### Spotify 的音乐推荐

```
Spotify 的 "Discover Weekly" 每周推荐:

  协同过滤:
    "和你听歌口味相似的人还听了..."

  内容分析:
    - 音频特征 (节奏、音调、能量)
    - 歌词分析 (NLP)
    - 艺术家关系图谱

  混合策略:
    70% 协同过滤 + 30% 内容分析 (大致比例)
    新用户: 更多依赖内容分析
    老用户: 更多依赖协同过滤
```

## 小结

- **内容推荐**分析物品本身的特征来做推荐，解决了冷启动问题，但容易陷入信息茧房
- **混合推荐**结合多种方法的优势，是工业界的主流做法
- 现代推荐系统本质上都是混合推荐——多路召回 + 统一排序，同时利用行为数据和内容特征
