# 推荐系统评估指标与 A/B 测试

> 如何判断一个推荐系统是好是坏？本文介绍离线评估指标、在线 A/B 测试方法，以及评估中的常见陷阱。

## 📊 离线评估指标

### 排序质量指标

#### AUC（Area Under ROC Curve）

```
最常用的 CTR 模型评估指标

含义: 随机取一个正样本和一个负样本，模型给正样本打分更高的概率

  AUC = 0.5  → 和随机猜一样差
  AUC = 0.7  → 还行
  AUC = 0.8  → 不错
  AUC = 0.9  → 很好

工业界精排模型的 AUC 通常在 0.75-0.85 之间
AUC 提升 0.001 在大规模系统中就可能带来显著的业务提升
```

#### GAUC（Group AUC）

```
AUC 的改进版，按用户分组计算后加权平均

  GAUC = Σ (用户i的样本数 × 用户i的AUC) / Σ 用户i的样本数

为什么需要 GAUC？
  全局 AUC 可能被活跃用户主导
  GAUC 更公平地反映每个用户的推荐质量
```

#### LogLoss（对数损失）

```
衡量预测概率的校准度

  LogLoss = -1/N × Σ [y × log(p) + (1-y) × log(1-p)]

  y: 真实标签 (0 或 1)
  p: 预测概率

  LogLoss 越小越好
  不仅要求排序正确，还要求预测概率准确
  → 对广告出价等需要精确概率的场景很重要
```

### 推荐列表质量指标

#### Precision@K 和 Recall@K

```
推荐了 K 个物品，其中:

  Precision@K = 用户实际喜欢的个数 / K
  "推荐的 K 个中有多少是对的"

  Recall@K = 用户实际喜欢的个数 / 用户喜欢的总数
  "用户喜欢的物品中有多少被推荐到了"

  例如: 推荐 10 个，用户喜欢其中 3 个，用户总共喜欢 20 个
  Precision@10 = 3/10 = 30%
  Recall@10 = 3/20 = 15%
```

#### NDCG@K（归一化折损累积增益）

```
考虑了推荐结果的位置——排在前面的更重要

  DCG@K = Σ (2^rel_i - 1) / log₂(i + 1)
  NDCG@K = DCG@K / IDCG@K  (除以理想排序的 DCG)

  例如推荐 5 个物品，相关性分别为 [3, 2, 0, 1, 0]:
  DCG = (2³-1)/log₂2 + (2²-1)/log₂3 + 0 + (2¹-1)/log₂5 + 0
      = 7/1 + 3/1.58 + 0 + 1/2.32 + 0
      = 7 + 1.89 + 0.43 = 9.32

  NDCG 的值在 0-1 之间，越大越好
  它惩罚把好物品排在后面的情况
```

#### MAP（Mean Average Precision）

```
对每个用户计算 AP，然后取平均

  AP = 1/R × Σ (Precision@k × rel(k))
  
  R: 相关物品总数
  rel(k): 第 k 个位置是否相关

  MAP 综合考虑了精确率和排序质量
```

#### Hit Rate（命中率）

```
最简单直观的指标

  Hit Rate@K = 有多少用户在 top-K 推荐中至少命中了一个 / 总用户数

  例如: 100 个用户，其中 60 个在 top-10 推荐中点击了至少一个
  Hit Rate@10 = 60%
```

### 多样性与覆盖率

```
多样性 (Diversity):
  推荐列表中物品之间的差异程度
  Diversity = 1 - avg_similarity(推荐列表中所有物品对)

覆盖率 (Coverage):
  被推荐过的物品占总物品的比例
  Coverage = |被推荐过的物品| / |总物品数|

  覆盖率低 → 大量长尾物品从未被推荐 → 马太效应

新颖性 (Novelty):
  推荐的物品有多"冷门"
  Novelty = avg(-log₂(popularity(item)))
  推荐越冷门的物品，新颖性越高
```

## 🧪 在线评估：A/B 测试

### 为什么离线指标不够

```
离线指标的局限:
  ❌ 只能评估已有数据中的物品（无法评估探索性推荐）
  ❌ 无法衡量用户体验（满意度、留存）
  ❌ 离线提升不一定带来在线提升
  ❌ 无法评估长期效果

经验法则:
  离线 AUC 提升 0.01 ≈ 在线 CTR 提升 1-3%（粗略估计）
  但这个关系不稳定，必须通过 A/B 测试验证
```

### A/B 测试流程

```
┌─────────────────────────────────────────────┐
│                                              │
│  Step 1: 确定实验目标                        │
│    主指标: CTR / 转化率 / 用户时长           │
│    护栏指标: 用户留存、DAU (不能变差)        │
│                                              │
│  Step 2: 流量分配                            │
│    ┌──────────────────────────────┐          │
│    │ 全量用户流量                  │          │
│    │  ├── 对照组 A (50%): 旧模型  │          │
│    │  └── 实验组 B (50%): 新模型  │          │
│    └──────────────────────────────┘          │
│    分流方式: 按用户 ID 哈希，保证同一用户     │
│    始终在同一组                               │
│                                              │
│  Step 3: 运行实验                            │
│    持续时间: 通常 7-14 天                    │
│    覆盖完整的周期 (工作日+周末)              │
│                                              │
│  Step 4: 统计检验                            │
│    计算 p-value，判断差异是否显著            │
│    p < 0.05 → 统计显著                       │
│                                              │
│  Step 5: 决策                                │
│    显著提升 → 全量上线                       │
│    不显著 → 继续优化或放弃                   │
│    显著下降 → 回滚                           │
│                                              │
└─────────────────────────────────────────────┘
```

### 核心在线指标

```
┌──────────────────────────────────────────────┐
│  指标              计算方式        意义       │
├──────────────────────────────────────────────┤
│  CTR              点击数/曝光数    吸引力     │
│  CVR              转化数/点击数    转化能力   │
│  人均观看时长      总时长/DAU      粘性       │
│  人均互动数        总互动/DAU      参与度     │
│  次日留存率        次日回访/DAU    长期价值   │
│  人均 GMV         总 GMV/DAU      商业价值   │
└──────────────────────────────────────────────┘

注意: 不同业务关注的核心指标不同
  短视频: 人均观看时长
  电商: GMV、转化率
  信息流: CTR、人均阅读量
```

### 分层实验

```
当同时有多个实验在跑时，需要分层:

  ┌─────────────────────────────────┐
  │ 召回层实验                       │
  │  ├── 实验 1: 新召回策略 (50%)   │
  │  └── 对照组 (50%)              │
  ├─────────────────────────────────┤
  │ 排序层实验                       │
  │  ├── 实验 2: 新排序模型 (50%)   │
  │  └── 对照组 (50%)              │
  ├─────────────────────────────────┤
  │ 重排层实验                       │
  │  ├── 实验 3: 新多样性策略 (50%) │
  │  └── 对照组 (50%)              │
  └─────────────────────────────────┘

  不同层的实验互不干扰
  同一层内的实验互斥（用户只在一个实验中）
  不同层的实验正交（用户可以同时参与多层实验）
```

### 常见陷阱

```
1. 辛普森悖论
   整体看 B 比 A 好，但分用户群看 A 都比 B 好
   → 需要分群分析

2. 新奇效应 (Novelty Effect)
   新策略刚上线时指标好，过几天就回落
   → 实验至少跑 7 天

3. 样本量不足
   流量太少导致结果不显著
   → 提前做功效分析 (Power Analysis)

4. 多重比较问题
   同时看 20 个指标，总有一个 p < 0.05
   → 用 Bonferroni 校正或 FDR 控制

5. 指标冲突
   CTR 提升但留存下降 (标题党)
   → 设置护栏指标，核心指标不能变差
```

## 📈 评估体系设计

```
完整的评估体系:

  离线评估 (快速迭代)
    ├── 离线数据集上的 AUC / NDCG
    ├── 回放测试 (Replay Evaluation)
    └── 通过 → 进入在线评估

  在线评估 (验证效果)
    ├── 小流量 A/B 测试 (5-10%)
    ├── 通过 → 扩大流量 (50%)
    └── 通过 → 全量上线

  长期监控 (持续跟踪)
    ├── 核心指标日报
    ├── 用户满意度调研
    └── 异常检测告警
```

## 小结

- 离线指标（AUC、NDCG）用于快速迭代，但不能替代在线评估
- A/B 测试是验证推荐效果的金标准
- 要同时关注效果指标（CTR）和体验指标（多样性、留存）
- 分层实验框架支持多个实验并行运行
- 评估是一个持续的过程，不是一次性的
