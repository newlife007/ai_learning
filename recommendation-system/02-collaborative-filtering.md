# 协同过滤：推荐系统的基石

> "和你口味相似的人喜欢什么，你大概率也会喜欢。" 这就是协同过滤的核心思想——利用群体智慧做推荐。它是推荐系统历史上最重要的算法家族。

## 💡 核心直觉

```
现实生活中的协同过滤:

  你的朋友小明和你电影口味很像:
    你们都喜欢《星际穿越》《盗梦空间》《信条》

  小明最近看了《奥本海默》并且打了 5 星

  → 你大概率也会喜欢《奥本海默》

  这就是协同过滤！
  "协同" = 利用其他用户的行为
  "过滤" = 从中筛选出你可能喜欢的
```

## 📊 用户-物品交互矩阵

协同过滤的基础数据结构——评分矩阵：

```
              电影A  电影B  电影C  电影D  电影E
  用户 Alice:   5     3      ?     1      ?
  用户 Bob:     4     ?      ?     1      ?
  用户 Carol:   1     1      ?     5      4
  用户 Dave:    ?     ?      5     4      ?
  用户 Eve:     ?     3      4     ?      5

  数字 = 评分 (1-5)
  ?   = 未评分 (需要预测的)

  推荐任务: 预测所有 "?" 的值，把预测分最高的推荐给用户
```

现实中这个矩阵极其稀疏——Netflix 的评分矩阵稀疏度超过 99%（用户只看过极少数电影）。

## 👥 基于用户的协同过滤（User-Based CF）

### 思路

```
Step 1: 找到和目标用户最相似的 K 个用户（"邻居"）
Step 2: 看这些邻居喜欢什么
Step 3: 把目标用户没看过但邻居们喜欢的物品推荐出来
```

### 用户相似度计算

**余弦相似度**（最常用）：

```
              电影A  电影B  电影C  电影D
  Alice:       5     3      4     1
  Bob:         4     ?      5     1

  共同评分的电影: A, D
  Alice 向量: (5, 1)
  Bob 向量:   (4, 1)

  cos(Alice, Bob) = (5×4 + 1×1) / (√(25+1) × √(16+1))
                  = 21 / (5.1 × 4.1)
                  = 0.99  → 非常相似！
```

**皮尔逊相关系数**（考虑评分偏差）：

```
有些用户打分偏高（"好好先生"），有些偏低（"严格评委"）
皮尔逊相关系数先减去各自的平均分，消除这种偏差

  Alice 平均分: 3.25    Bob 平均分: 3.33
  Alice 去均值: (1.75, -2.25)
  Bob 去均值:   (0.67, -2.33)

  pearson = Σ(a_i - ā)(b_i - b̄) / √(Σ(a_i - ā)² × Σ(b_i - b̄)²)
```

### 预测评分

```
预测 Alice 对电影 C 的评分:

  找到 Alice 的 K 个最相似用户 (假设 K=2):
    Bob (相似度 0.99), Eve (相似度 0.85)

  Bob 对电影 C 的评分: 5
  Eve 对电影 C 的评分: 4

  加权平均:
  pred = (0.99 × 5 + 0.85 × 4) / (0.99 + 0.85)
       = (4.95 + 3.40) / 1.84
       = 4.54

  → 预测 Alice 会给电影 C 打 4.54 分，值得推荐！
```

### User-Based CF 的问题

```
❌ 用户数量巨大 (亿级)，计算所有用户对的相似度成本极高
❌ 用户兴趣变化快，相似度需要频繁更新
❌ 新用户没有历史行为，无法计算相似度（冷启动）
```

## 📦 基于物品的协同过滤（Item-Based CF）

Amazon 在 2003 年提出，至今仍被广泛使用。

### 思路

```
Step 1: 计算物品之间的相似度（基于用户的共同行为）
Step 2: 对于目标用户，找到他喜欢的物品
Step 3: 推荐与这些物品最相似的其他物品
```

### 物品相似度

```
              用户1  用户2  用户3  用户4  用户5
  电影 A:       5     4      1      ?      ?
  电影 B:       3     ?      1      ?      3
  电影 C:       ?     5      ?      5      4

  电影 A 和 B 的相似度:
    共同被评分的用户: 用户1, 用户3
    A 向量: (5, 1)
    B 向量: (3, 1)
    cos(A, B) = (15+1) / (√26 × √10) = 0.99

  电影 A 和 C 的相似度:
    共同被评分的用户: 用户2
    只有一个共同用户，相似度不可靠
```

### 为什么 Item-Based 比 User-Based 更实用

```
┌──────────────────┬──────────────────┐
│   User-Based     │   Item-Based     │
├──────────────────┼──────────────────┤
│ 用户数: 亿级     │ 物品数: 百万级   │
│ 用户兴趣常变     │ 物品属性稳定     │
│ 相似度需频繁更新 │ 相似度可离线算好 │
│ 可解释性差       │ "因为你看了 A    │
│                  │  所以推荐 B"     │
│ 适合用户少的场景 │ 适合物品少的场景 │
└──────────────────┴──────────────────┘

Amazon 的经典推荐 "买了这个商品的人也买了..."
就是 Item-Based CF 的直接应用
```

## 🔢 矩阵分解（Matrix Factorization）

2006-2009 年 Netflix Prize 竞赛中大放异彩的方法，将协同过滤推向了新高度。

### 核心思想

```
把稀疏的 用户×物品 评分矩阵，分解为两个低维矩阵的乘积:

  R ≈ P × Q^T

  R: m×n 评分矩阵 (m 个用户, n 个物品)
  P: m×k 用户隐向量矩阵 (每个用户用 k 维向量表示)
  Q: n×k 物品隐向量矩阵 (每个物品用 k 维向量表示)

  k 通常取 50-200，远小于 m 和 n
```

### 直觉理解

```
假设 k=3，隐向量的每个维度可能代表:

  维度 1: 动作片 ←→ 文艺片
  维度 2: 好莱坞 ←→ 独立电影
  维度 3: 新片 ←→ 经典老片

  用户 Alice 的隐向量: [0.9, -0.3, 0.5]
    → 喜欢动作片、偏好好莱坞、喜欢经典

  电影《终结者》的隐向量: [0.8, -0.5, 0.7]
    → 动作片、好莱坞、经典

  预测评分 = Alice · 终结者 = 0.9×0.8 + (-0.3)×(-0.5) + 0.5×0.7
           = 0.72 + 0.15 + 0.35 = 1.22 → 标准化后约 4.2 分

  向量越接近，预测评分越高 → 推荐！
```

### SVD 分解

```
最小化目标:

  min Σ (r_ui - p_u · q_i)² + λ(||p_u||² + ||q_i||²)
  (u,i)∈已知评分

  第一项: 预测值与真实值的误差
  第二项: 正则化，防止过拟合

训练方法:
  - SGD (随机梯度下降): 简单高效
  - ALS (交替最小二乘): 适合并行计算
```

### 加入偏置项

不同用户和物品有不同的"基准线"：

```
  r̂_ui = μ + b_u + b_i + p_u · q_i

  μ:   全局平均分 (比如 3.5)
  b_u: 用户偏置 (Alice 打分偏高 +0.3)
  b_i: 物品偏置 (这部电影普遍评价高 +0.8)
  p_u · q_i: 个性化部分

  例如:
  预测 = 3.5 + 0.3 + 0.8 + 1.22 = 5.82 → 截断为 5.0
```

### Netflix Prize 的启示

```
Netflix Prize (2006-2009):
  奖金: 100 万美元
  目标: 将推荐准确率提升 10%
  
  关键发现:
  1. 矩阵分解效果远超传统 CF
  2. 模型融合 (Ensemble) 能进一步提升
  3. 时间因素很重要（用户兴趣会变）
  
  获胜方案: 融合了 100+ 个模型
  
  但 Netflix 最终没有上线获胜方案
  → 工程复杂度太高，性价比不够
  → 工业界需要的是简单有效的方案
```

## 🔄 隐式反馈的协同过滤

现实中评分数据很少，更多的是隐式反馈（点击、浏览、购买）：

```
显式反馈:  r_ui = 4 (用户给了 4 分)
隐式反馈:  r_ui = 1 (用户点击了) 或 0 (用户没点击)

问题: 没点击 ≠ 不喜欢，可能只是没看到
```

### BPR（Bayesian Personalized Ranking）

专门为隐式反馈设计的方法：

```
核心思想: 用户交互过的物品应该排在没交互过的前面

  对于用户 u:
    正样本 i: 用户点击过的物品
    负样本 j: 用户没点击过的物品（随机采样）

  优化目标:
    max Σ log σ(r̂_ui - r̂_uj)
    
    即: 让正样本的预测分 > 负样本的预测分
```

### ALS for Implicit Feedback

```
将隐式反馈转化为置信度:

  c_ui = 1 + α × r_ui

  r_ui = 0 (没交互): 置信度 = 1 (低置信度认为不喜欢)
  r_ui = 10 (点击10次): 置信度 = 1 + 40×10 = 401 (高置信度认为喜欢)

  然后用加权矩阵分解求解
```

## 📐 协同过滤的局限性

```
┌─────────────────────────────────────────────┐
│  局限性              说明                    │
├─────────────────────────────────────────────┤
│  冷启动              新用户/新物品无法推荐   │
│  数据稀疏            大部分评分是空的        │
│  无法利用内容特征    只看行为，不看物品本身   │
│  流行度偏差          倾向推荐热门物品        │
│  可扩展性            用户/物品增长后计算量大  │
│  无法捕捉上下文      不考虑时间、地点等因素  │
└─────────────────────────────────────────────┘

→ 这些局限催生了后续的内容推荐、深度学习推荐等方法
```

## 🛠️ 快速实践：用 Python 实现简单的协同过滤

```python
import numpy as np

# 评分矩阵 (0 表示未评分)
R = np.array([
    [5, 3, 0, 1, 0],
    [4, 0, 0, 1, 0],
    [1, 1, 0, 5, 4],
    [0, 0, 5, 4, 0],
    [0, 3, 4, 0, 5],
])

# 简单矩阵分解 (SGD)
def matrix_factorization(R, k=3, lr=0.01, reg=0.02, epochs=5000):
    m, n = R.shape
    P = np.random.rand(m, k) * 0.1
    Q = np.random.rand(n, k) * 0.1
    
    for _ in range(epochs):
        for u in range(m):
            for i in range(n):
                if R[u][i] > 0:  # 只对已知评分训练
                    err = R[u][i] - P[u] @ Q[i]
                    P[u] += lr * (err * Q[i] - reg * P[u])
                    Q[i] += lr * (err * P[u] - reg * Q[i])
    return P, Q

P, Q = matrix_factorization(R)
predicted = P @ Q.T
print("预测评分矩阵:")
print(np.round(predicted, 1))
# 对于 R 中为 0 的位置，predicted 的值就是推荐分数
```

## 小结

协同过滤是推荐系统最经典的方法家族：
- **User-Based CF**：找相似用户，适合用户少的场景
- **Item-Based CF**：找相似物品，工业界更常用
- **矩阵分解**：用隐向量表示用户和物品，效果更好

它的核心假设是"行为相似的用户有相似的偏好"。虽然有冷启动、稀疏性等局限，但协同过滤的思想至今仍是推荐系统的基石。
