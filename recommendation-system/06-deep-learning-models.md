# 深度学习推荐模型演进

> 从 2016 年 Google 的 Wide & Deep 开始，深度学习彻底改变了推荐系统的精排阶段。本文梳理最重要的深度推荐模型，理解每个模型解决了什么问题。

## 📜 模型演进全景

```
时间线:

  LR (逻辑回归)                    ← 最简单的基线
    ↓
  POLY2 / FM (2010)                ← 自动特征交叉
    ↓
  GBDT + LR (Facebook, 2014)      ← 自动特征组合
    ↓
  Wide & Deep (Google, 2016)       ← 深度学习入场
    ↓
  DeepFM (2017)                    ← FM + Deep 端到端
    ↓
  DIN (阿里, 2018)                 ← 注意力机制
    ↓
  DIEN (阿里, 2019)                ← 兴趣演化
    ↓
  MMOE / PLE (2018-2020)           ← 多任务学习
    ↓
  DCN v2 (Google, 2021)            ← 高阶显式交叉
    ↓
  Transformer-based (2020+)        ← 序列建模
```

## 1️⃣ FM：因子分解机（2010）

### 解决的问题

```
LR 的局限: 只能学习一阶特征，无法捕捉特征交叉

  例如: "性别=女" 和 "类别=化妆品" 单独看都不强
        但 "女性 + 化妆品" 的组合是强信号

  手动交叉: 特征数 n，二阶交叉 n² 个 → 组合爆炸
  而且稀疏数据中很多交叉特征没有训练样本
```

### FM 的方案

```
为每个特征学习一个 k 维隐向量:

  ŷ = w₀ + Σ wᵢxᵢ + Σ Σ <vᵢ, vⱼ> xᵢxⱼ
                       i j>i

  第一项: 偏置
  第二项: 一阶特征 (和 LR 一样)
  第三项: 二阶特征交叉 (用向量内积代替独立参数)

  参数量: O(nk) 而非 O(n²)
  
  关键优势: 即使特征 i 和 j 从未同时出现
  只要 vᵢ 和 vⱼ 各自通过其他交叉学到了好的表示
  <vᵢ, vⱼ> 仍然能给出合理的预测
```

## 2️⃣ Wide & Deep（Google, 2016）

Google Play 应用商店推荐的里程碑模型。

### 核心思想

```
┌─────────────────────────────────────────────┐
│                                              │
│  Wide 部分              Deep 部分            │
│  (记忆能力)             (泛化能力)           │
│                                              │
│  手动交叉特征            原始特征             │
│  "已安装App×曝光App"     Embedding 化         │
│       ↓                      ↓               │
│  线性模型 (LR)          多层 MLP              │
│       ↓                      ↓               │
│       └──────── 拼接 ────────┘               │
│                  ↓                            │
│              Sigmoid                          │
│                  ↓                            │
│            P(下载)                            │
└─────────────────────────────────────────────┘

Wide: 记住 "用户安装了 A，曝光了 B → 会下载" 这种规则
Deep: 泛化到 "喜欢 A 类 App 的用户可能也喜欢 B 类"
```

### 为什么需要 Wide

```
纯 Deep 模型的问题: 过度泛化
  用户明确不喜欢某类内容，但 Deep 模型可能仍然推荐
  因为 Deep 学到的是泛化的模式

Wide 的作用: 记住特定的规则
  "这个用户点了不喜欢 → 不要再推类似的"
  这种精确的记忆需要 Wide 部分来保证
```

## 3️⃣ DeepFM（2017）

### 解决的问题

Wide & Deep 的 Wide 部分需要手动设计交叉特征，DeepFM 用 FM 替代 Wide，实现端到端自动交叉。

```
┌─────────────────────────────────────────────┐
│                                              │
│  FM 部分                Deep 部分            │
│  (自动二阶交叉)         (高阶交叉)           │
│                                              │
│  共享 Embedding 层                           │
│  ┌─────────────────────────────────┐        │
│  │ 特征1_emb  特征2_emb  特征3_emb │        │
│  └─────────────────────────────────┘        │
│       ↓                      ↓               │
│  FM 交叉计算            多层 MLP              │
│  Σ<vᵢ,vⱼ>xᵢxⱼ              ↓               │
│       ↓                      ↓               │
│       └──────── 拼接 ────────┘               │
│                  ↓                            │
│              Sigmoid → P(click)               │
└─────────────────────────────────────────────┘

关键改进:
  ✅ FM 和 Deep 共享 Embedding → 端到端训练
  ✅ 不需要手动设计交叉特征
  ✅ FM 捕捉二阶交叉，Deep 捕捉高阶交叉
```

## 4️⃣ DIN：深度兴趣网络（阿里, 2018）

### 解决的问题

```
之前的模型: 用户的历史行为被简单地求平均/求和

  用户看过: [连衣裙, 手机壳, 运动鞋, 口红, 数据线]
  用户表示 = mean(连衣裙_emb, 手机壳_emb, ..., 数据线_emb)

  问题: 当候选物品是 "高跟鞋" 时
        "连衣裙" 和 "口红" 应该更重要
        "手机壳" 和 "数据线" 不太相关
        但平均操作把它们同等对待了
```

### DIN 的方案：注意力机制

```
┌─────────────────────────────────────────────┐
│                                              │
│  候选物品: 高跟鞋                            │
│       ↓                                      │
│  计算与每个历史行为的注意力权重:              │
│                                              │
│  连衣裙  ──→ Attention(连衣裙, 高跟鞋) = 0.4 │ ← 相关！
│  手机壳  ──→ Attention(手机壳, 高跟鞋) = 0.05│
│  运动鞋  ──→ Attention(运动鞋, 高跟鞋) = 0.3 │ ← 相关！
│  口红    ──→ Attention(口红, 高跟鞋)   = 0.2 │ ← 有点相关
│  数据线  ──→ Attention(数据线, 高跟鞋) = 0.05│
│                                              │
│  用户兴趣 = 0.4×连衣裙 + 0.05×手机壳        │
│           + 0.3×运动鞋 + 0.2×口红            │
│           + 0.05×数据线                       │
│                                              │
│  → 用户兴趣表示会偏向与候选物品相关的行为     │
└─────────────────────────────────────────────┘

核心洞察: 用户兴趣是多样的，不同候选物品应该激活不同的兴趣
```

## 5️⃣ DIEN：深度兴趣演化网络（阿里, 2019）

### 解决的问题

```
DIN 把历史行为当作无序集合，忽略了兴趣的时间演化

  用户行为序列 (按时间):
  T1: 浏览手机 → T2: 浏览手机壳 → T3: 购买手机
  → T4: 浏览耳机 → T5: 浏览音箱

  兴趣在演化: 手机相关 → 配件相关 → 音频设备
  
  DIEN 用 GRU 建模这种兴趣演化过程
```

### DIEN 架构

```
行为序列: [item1, item2, item3, item4, item5]
              ↓      ↓      ↓      ↓      ↓
           ┌─────────────────────────────────┐
           │  兴趣提取层 (GRU)               │
           │  h1 → h2 → h3 → h4 → h5       │
           └─────────────────────────────────┘
              ↓      ↓      ↓      ↓      ↓
           ┌─────────────────────────────────┐
           │  兴趣演化层 (AUGRU)             │
           │  用注意力加权的 GRU              │
           │  候选物品决定关注哪条兴趣线      │
           └─────────────────────────────────┘
                                          ↓
                                    最终兴趣表示
                                          ↓
                                    预测 P(click)
```

## 6️⃣ 多任务学习：MMOE 与 PLE

### 为什么需要多任务

```
推荐系统需要同时预测多个目标:
  - P(点击)
  - P(点赞)
  - P(收藏)
  - P(购买)
  - E(观看时长)

简单做法: 每个目标训练一个独立模型 → 参数多、维护成本高
多任务学习: 共享底层表示，各任务有独立的输出头
```

### MMOE（Multi-gate Mixture-of-Experts）

```
┌─────────────────────────────────────────────┐
│                                              │
│  输入特征                                    │
│     ↓                                        │
│  ┌────────┐ ┌────────┐ ┌────────┐           │
│  │Expert 1│ │Expert 2│ │Expert 3│  共享专家  │
│  └────────┘ └────────┘ └────────┘           │
│     ↓  ↓  ↓    ↓  ↓  ↓    ↓  ↓  ↓          │
│  ┌──────────┐        ┌──────────┐           │
│  │ Gate A   │        │ Gate B   │  每个任务  │
│  │ 软选择   │        │ 软选择   │  有自己的  │
│  │ 专家组合 │        │ 专家组合 │  门控网络  │
│  └──────────┘        └──────────┘           │
│       ↓                    ↓                 │
│  ┌──────────┐        ┌──────────┐           │
│  │ Tower A  │        │ Tower B  │  任务塔    │
│  │ P(点击)  │        │ P(购买)  │           │
│  └──────────┘        └──────────┘           │
└─────────────────────────────────────────────┘

Gate 的作用: 不同任务可以选择不同的专家组合
  点击任务: 更多依赖 Expert 1 和 2
  购买任务: 更多依赖 Expert 2 和 3
```

### PLE（Progressive Layered Extraction）

```
MMOE 的改进: 每个任务有自己的专属专家 + 共享专家

  ┌──────────┐ ┌──────────┐ ┌──────────┐
  │任务A专家  │ │ 共享专家  │ │任务B专家  │
  └──────────┘ └──────────┘ └──────────┘
       ↓             ↓             ↓
  ┌──────────┐              ┌──────────┐
  │ Gate A   │              │ Gate B   │
  └──────────┘              └──────────┘

  → 减少任务之间的负迁移 (一个任务的优化损害另一个任务)
```

## 7️⃣ DCN v2（Google, 2021）

### 核心思想：显式高阶特征交叉

```
普通 MLP 学习特征交叉是隐式的，效率不高
DCN v2 用 Cross Network 显式地学习高阶交叉:

  x_{l+1} = x_0 ⊙ (W_l · x_l + b_l) + x_l

  每一层 Cross Layer 都与原始输入 x_0 做交叉
  L 层 Cross Network 可以学到 L+1 阶的特征交叉

  例如 2 层:
    第 1 层: 学到 x_i × x_j (二阶)
    第 2 层: 学到 x_i × x_j × x_k (三阶)
```


## 🔮 前沿方向

### Transformer 在推荐中的应用

```
用户行为序列天然适合 Transformer:

  SASRec: 用 Self-Attention 建模行为序列
  BERT4Rec: 用 BERT 的 MLM 方式训练序列推荐
  SIM: 用 Transformer 处理超长行为序列 (阿里)

  优势: 并行计算、长距离依赖、效果好
  挑战: 计算成本高，需要优化推理效率
```

### LLM + 推荐

```
大语言模型在推荐中的探索:

  1. LLM 作为特征提取器:
     用 LLM 理解物品的文本描述 → 生成更好的 Embedding

  2. LLM 作为推荐引擎:
     "根据用户看过 [A, B, C]，推荐下一个物品"
     → 直接用 LLM 的生成能力做推荐

  3. 对话式推荐:
     用户: "我想看一部轻松的喜剧"
     LLM: "根据你之前喜欢的《xxx》，推荐..."
```

## 小结

深度学习推荐模型的演进遵循一条清晰的主线：
- **FM → DeepFM**：从手动到自动的特征交叉
- **DIN → DIEN**：从静态到动态的用户兴趣建模
- **MMOE → PLE**：从单任务到多任务的联合优化
- **MLP → Transformer**：从简单到复杂的序列建模

每个模型都是在前一个的基础上解决了一个具体问题。理解这条演进线，就理解了推荐系统精排的核心技术。
