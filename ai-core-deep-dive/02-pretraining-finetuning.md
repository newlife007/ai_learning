# 预训练与微调：从 GPT 到 LLaMA

> 大模型的能力从何而来？本文解析预训练和微调的完整流程，以及从 GPT 到 LLaMA 的技术演进。

## 两阶段范式

现代 LLM 的训练遵循一个清晰的两阶段范式：

```
阶段 1: 预训练 (Pre-training)
  海量文本 → 学习语言的通用表示 → 基座模型 (Base Model)
  
阶段 2: 微调 (Fine-tuning)
  基座模型 + 特定任务数据 → 对齐/专业化 → 可用模型
```

预训练赋予模型"知识"，微调赋予模型"行为"。

## 预训练

### 训练目标

不同架构使用不同的预训练目标：

| 架构 | 目标 | 示例 |
|------|------|------|
| Decoder-only (GPT) | 下一个 token 预测 (CLM) | "今天天气" → "很" |
| Encoder-only (BERT) | 掩码语言模型 (MLM) | "今天[MASK]气很好" → "天" |
| Encoder-Decoder (T5) | Span Corruption | "今天<X>很好" → "<X>天气" |

当前主流是 **CLM（Causal Language Modeling）**——给定前文，预测下一个 token。看似简单，但在足够大的数据和模型规模下，这个目标能让模型学到推理、编程、数学等复杂能力。

### 训练数据

数据质量直接决定模型质量。典型的预训练数据组成：

```
Common Crawl (网页)     ~60%   ← 经过严格清洗和去重
书籍                    ~15%
代码 (GitHub)           ~10%
Wikipedia               ~5%
学术论文 (ArXiv)        ~5%
其他 (StackOverflow等)  ~5%
```

数据处理流程：
1. **去重**：MinHash / SimHash 去除近似重复
2. **质量过滤**：基于困惑度、语言检测、有害内容过滤
3. **数据配比**：不同来源按比例混合，代码和数学数据通常会上采样

LLaMA 1 用 1.4T tokens 训练，LLaMA 2 用 2T tokens，LLaMA 3 用 15T+ tokens。数据量的增长远超参数量的增长。

### Scaling Laws

Kaplan et al. (2020) 和 Chinchilla (2022) 揭示了关键规律：

```
Chinchilla 最优: 训练 tokens ≈ 20 × 参数量

例如:
  7B 模型 → 最优 140B tokens
  70B 模型 → 最优 1.4T tokens
```

但实际中，由于推理成本的考虑，趋势是用更多数据训练更小的模型（over-training）。LLaMA 3 8B 用了 15T tokens，远超 Chinchilla 最优的 160B。

### 训练基础设施

预训练一个大模型需要：

| 模型规模 | GPU 数量 | 训练时间 | 估算成本 |
|---------|---------|---------|---------|
| 7B | 64× A100 | ~2 周 | ~$100K |
| 70B | 512× A100 | ~1 月 | ~$2M |
| 405B (LLaMA 3) | 16K× H100 | ~2 月 | ~$30M+ |

关键技术：
- **3D 并行**：数据并行 + 张量并行 + 流水线并行
- **混合精度训练**：BF16/FP16 + FP32 主权重
- **ZeRO 优化**：分片优化器状态、梯度、参数
- **梯度检查点**：用计算换显存

## 微调

### 全量微调 vs 参数高效微调

| 方法 | 可训练参数 | 显存需求 | 效果 |
|------|-----------|---------|------|
| 全量微调 | 100% | 极高 | 最好 |
| LoRA | ~0.1-1% | 低 | 接近全量 |
| QLoRA | ~0.1-1% | 极低 | 略低于 LoRA |
| Prompt Tuning | <0.01% | 极低 | 简单任务够用 |

### LoRA（Low-Rank Adaptation）

当前最流行的微调方法。核心思想：冻结原始权重，只训练低秩分解的增量矩阵。

```
原始: Y = W · X           (W: d×d 矩阵)
LoRA: Y = W · X + B·A · X  (A: d×r, B: r×d, r << d)

例如 d=4096, r=16:
  原始参数: 4096 × 4096 = 16.7M
  LoRA 参数: 4096 × 16 + 16 × 4096 = 131K (0.8%)
```

LoRA 的关键超参数：
- **rank (r)**：通常 8-64，越大表达能力越强但参数越多
- **alpha**：缩放因子，通常设为 rank 的 2 倍
- **目标模块**：通常应用于 Q、K、V、O 投影矩阵

### QLoRA

在 LoRA 基础上，将基座模型量化到 4-bit，进一步降低显存：

```
QLoRA = 4-bit 量化基座模型 + BF16 LoRA 适配器

70B 模型微调显存: ~160GB (全量) → ~35GB (QLoRA, 单卡 A100)
```

### 指令微调（Instruction Tuning）

将基座模型变成能遵循指令的助手模型：

```json
{
  "instruction": "将以下英文翻译成中文",
  "input": "The weather is nice today.",
  "output": "今天天气很好。"
}
```

关键数据集：
- **FLAN**：Google 的多任务指令数据集
- **Alpaca**：Stanford 用 GPT-3.5 生成的 52K 指令数据
- **OpenHermes**：高质量合成指令数据

指令微调的数据量通常在 10K-1M 条，远少于预训练数据，但对模型行为的影响巨大。

### 对话微调

在指令微调基础上，进一步训练多轮对话能力：

```
<|system|>你是一个有帮助的助手。
<|user|>什么是量子计算？
<|assistant|>量子计算是利用量子力学原理...
<|user|>它和经典计算有什么区别？
<|assistant|>主要区别在于...
```

## 从 GPT 到 LLaMA 的演进

### GPT 系列

```
GPT-1 (2018): 117M 参数，证明预训练+微调范式有效
  ↓
GPT-2 (2019): 1.5B 参数，zero-shot 能力涌现
  ↓
GPT-3 (2020): 175B 参数，in-context learning，few-shot 惊艳
  ↓
InstructGPT (2022): GPT-3 + RLHF，对齐人类偏好
  ↓
GPT-4 (2023): MoE 架构 (推测)，多模态，推理能力飞跃
```

### LLaMA 系列

Meta 的开源路线，推动了整个开源生态：

```
LLaMA 1 (2023.02):
  - 7B/13B/33B/65B
  - 1.4T tokens 训练
  - 证明小模型+更多数据 > 大模型+少数据

LLaMA 2 (2023.07):
  - 7B/13B/70B + Chat 版本
  - 2T tokens，上下文 4096
  - 引入 GQA，开源 RLHF 流程

LLaMA 3 (2024.04):
  - 8B/70B/405B
  - 15T+ tokens，上下文 128K
  - 接近 GPT-4 水平的开源模型
```

## 实践建议

1. **选择基座模型**：优先选择与目标任务语言/领域匹配的模型
2. **数据质量 > 数量**：1000 条高质量数据 > 10000 条噪声数据
3. **先试 LoRA**：大多数场景下 LoRA 就够了，全量微调是最后手段
4. **评估很重要**：微调后务必在独立测试集上评估，防止过拟合
5. **学习率**：微调学习率通常是预训练的 1/10 到 1/100

## 小结

预训练和微调构成了现代 LLM 的基本训练范式。预训练通过海量数据赋予模型通用能力，微调通过少量高质量数据将模型调整到特定用途。LoRA 等参数高效方法让普通开发者也能定制自己的模型。
