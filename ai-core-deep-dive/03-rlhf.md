# RLHF：让 AI 对齐人类偏好

> 预训练让模型学会了语言，指令微调让模型学会了遵循指令，但模型仍然可能输出有害、不诚实或无用的内容。RLHF 是让模型真正"好用"的关键一步。

## 为什么需要 RLHF

一个只经过预训练和指令微调的模型存在明显问题：

- **讨好用户**：即使用户的前提是错的，模型也会顺着说
- **编造事实**：自信地输出不存在的信息（幻觉）
- **有害输出**：可能生成有毒、偏见或危险内容
- **冗长啰嗦**：倾向于生成过长的回答

RLHF 的目标是让模型的输出对齐三个原则（来自 InstructGPT 论文）：
1. **有帮助 (Helpful)**：准确、相关地回答用户问题
2. **诚实 (Honest)**：不编造信息，承认不确定性
3. **无害 (Harmless)**：拒绝有害请求，不输出有毒内容

## RLHF 三步流程

```
Step 1: SFT (Supervised Fine-Tuning)
  基座模型 + 人工标注的高质量对话 → SFT 模型

Step 2: 训练奖励模型 (Reward Model)
  同一问题生成多个回答 → 人工排序 → 训练 RM 打分

Step 3: PPO 强化学习优化
  SFT 模型 + RM 反馈 → 迭代优化 → RLHF 模型
```

### Step 1: SFT

这一步和指令微调基本相同，但数据质量要求更高。通常由专业标注员编写示范回答：

```
Prompt: "解释什么是黑洞"
标注员回答: "黑洞是一种天体，其引力极强，以至于..."
```

数据量通常在 10K-100K 条。

### Step 2: 奖励模型（Reward Model）

这是 RLHF 最核心的创新。与其让人类直接写出"完美回答"，不如让人类比较两个回答哪个更好——这对人类来说容易得多。

```
Prompt: "如何学习编程？"

回答 A: "你可以从 Python 开始，推荐以下学习路径..."
回答 B: "编程很简单，随便学学就行了。"

人类标注: A > B
```

训练过程：
1. 用 SFT 模型对同一 prompt 生成 K 个回答（通常 K=4）
2. 人工对 K 个回答进行排序
3. 从排序中提取 C(K,2) 个偏好对
4. 用 Bradley-Terry 模型训练 RM

**损失函数：**

```
L(θ) = -E[log σ(r_θ(x, y_w) - r_θ(x, y_l))]

其中:
  r_θ: 奖励模型的打分
  y_w: 人类偏好的（更好的）回答
  y_l: 人类不偏好的（更差的）回答
  σ: sigmoid 函数
```

直觉：让 RM 给好回答打更高分，给差回答打更低分。

### Step 3: PPO 优化

用强化学习（PPO 算法）优化 SFT 模型，使其生成的回答获得更高的 RM 分数：

```
目标: max E[r_θ(x, y)] - β · KL(π_RL || π_SFT)

其中:
  r_θ(x, y): RM 对生成回答的打分
  KL(...): 新策略与 SFT 模型的 KL 散度
  β: KL 惩罚系数
```

KL 散度惩罚至关重要——防止模型为了讨好 RM 而偏离太远（reward hacking）。没有 KL 约束，模型可能学会生成"RM 喜欢但人类觉得奇怪"的回答。

**PPO 训练中涉及 4 个模型：**

```
1. 策略模型 (Actor): 正在被优化的模型
2. 参考模型 (Reference): 冻结的 SFT 模型，用于计算 KL
3. 奖励模型 (RM): 打分器
4. 价值模型 (Critic): 估计状态价值，减少方差
```

这也是 RLHF 训练成本高的原因——需要同时加载 4 个大模型。

## DPO：更简单的替代方案

PPO 训练复杂且不稳定。2023 年提出的 DPO（Direct Preference Optimization）提供了一种更优雅的方案：

**核心思想：** 跳过奖励模型训练，直接从偏好数据优化策略模型。

```
DPO 损失:
L(θ) = -E[log σ(β · (log π_θ(y_w|x)/π_ref(y_w|x) 
                     - log π_θ(y_l|x)/π_ref(y_l|x)))]
```

**DPO vs PPO：**

| 维度 | PPO | DPO |
|------|-----|-----|
| 需要 RM | 是 | 否 |
| 训练稳定性 | 低（超参敏感） | 高 |
| 显存需求 | 4 个模型 | 2 个模型 |
| 实现复杂度 | 高 | 低（类似 SFT） |
| 效果 | 略好（理论上） | 接近 PPO |

DPO 已成为开源社区的主流选择。LLaMA 2 用 PPO，但很多后续模型转向了 DPO 或其变体。

## 其他对齐方法

### RLAIF（AI 反馈的强化学习）

用 AI 替代人类标注偏好数据：

```
Prompt → 模型生成多个回答 → 强大的 AI (如 GPT-4) 评判排序 → 训练 RM
```

Anthropic 的 Constitutional AI 就是这个思路——用 AI 自我批评和修正。

### KTO（Kahneman-Tversky Optimization）

不需要偏好对，只需要"好/坏"二元标签：

```
传统: (prompt, 好回答, 坏回答) → 偏好对
KTO:  (prompt, 回答, 好/坏标签) → 直接优化
```

数据收集成本更低，适合从用户反馈（点赞/点踩）中学习。

### ORPO（Odds Ratio Preference Optimization）

将 SFT 和偏好优化合并为一步，进一步简化流程。

## 实际效果

InstructGPT 论文中的关键发现：

```
1.3B 参数的 RLHF 模型 > 175B 参数的 SFT 模型（人类评估）
```

这说明对齐训练的价值远超单纯的规模扩展。

## 当前挑战

1. **Reward Hacking**：模型学会利用 RM 的漏洞获取高分，而非真正提升质量
2. **标注一致性**：不同标注员对"好回答"的标准不同
3. **过度安全**：RLHF 后模型可能过度拒绝，对无害问题也说"我不能回答"
4. **评估困难**：如何客观衡量对齐效果仍是开放问题

## 小结

RLHF 是将"能说话的模型"变成"好用的助手"的关键技术。虽然 PPO 训练复杂，但 DPO 等简化方法让对齐训练变得更加可及。对齐不仅是技术问题，更涉及"什么是好的 AI 行为"这一根本性问题。
