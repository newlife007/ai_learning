# Embedding 与向量数据库

> Embedding 是将文本、图像等非结构化数据转换为数值向量的技术，是 RAG、语义搜索、推荐系统等应用的基础。向量数据库则是高效存储和检索这些向量的基础设施。

## 什么是 Embedding

```
"机器学习很有趣" → Embedding 模型 → [0.12, -0.34, 0.56, ..., 0.78]
                                      (768 维或 1536 维浮点数向量)
```

核心性质：**语义相似的文本，向量距离更近。**

```
cos("机器学习很有趣", "AI 非常有意思") ≈ 0.92  (高相似度)
cos("机器学习很有趣", "今天天气不错")   ≈ 0.15  (低相似度)
```

## Embedding 模型的训练

### 对比学习（Contrastive Learning）

主流训练方法。核心思想：拉近正样本对，推远负样本对。

```
正样本对: (问题, 对应答案) / (查询, 相关文档)
负样本对: (问题, 不相关文档)

损失函数 (InfoNCE):
L = -log(exp(sim(q, d+)/τ) / Σ exp(sim(q, di)/τ))

其中:
  q: 查询向量
  d+: 正样本向量
  di: 所有样本（正+负）
  τ: 温度参数
```

### 训练数据来源

| 数据类型 | 示例 | 用途 |
|---------|------|------|
| 问答对 | (问题, 答案) | 检索能力 |
| 标题-正文 | (标题, 文章内容) | 语义匹配 |
| 查询-文档 | (搜索词, 点击文档) | 搜索相关性 |
| 翻译对 | (中文, 英文) | 跨语言能力 |
| 合成数据 | LLM 生成的正负样本 | 扩充训练数据 |

### 训练阶段

现代 Embedding 模型通常分三阶段训练：

```
1. 预训练: 大规模弱监督数据（标题-正文对等）
2. 微调: 高质量标注数据 + 难负样本挖掘
3. 蒸馏 (可选): 从大模型蒸馏到小模型
```

**难负样本挖掘（Hard Negative Mining）** 是提升效果的关键——不是随机选负样本，而是选那些"看起来相关但实际不相关"的样本。

| 模型 | 维度 | 最大长度 | 特点 |

| OpenAI text-embedding-3-large | 3072 | 8191 | 更高精度 |

### 选择建议

- **中文场景**：BGE 系列 或 GTE-Qwen2
- **多语言**：BGE-M3 或 Jina-embeddings-v3
- **商用简单**：OpenAI text-embedding-3-small
- **极致效果**：GTE-Qwen2-7B 或 E5-mistral-7b

## 相似度计算

| 方法 | 公式 | 特点 |
|------|------|------|
| 余弦相似度 | cos(a,b) = a·b / (\|a\|·\|b\|) | 最常用，归一化后等价于内积 |
| 内积 | a·b | 向量归一化后等价于余弦 |
| 欧氏距离 | \|\|a-b\|\| | 距离越小越相似 |

实践中几乎都用余弦相似度。大多数 Embedding 模型输出的向量已经归一化，此时余弦相似度 = 内积。

## 向量数据库

### 为什么需要专门的向量数据库

暴力搜索（遍历所有向量计算相似度）在数据量大时不可行：

```
100 万条 1536 维向量:
  暴力搜索: ~100ms (可接受)
  
1 亿条 1536 维向量:
  暴力搜索: ~10s (不可接受)
  ANN 索引: ~5ms (可接受，召回率 >95%)
```

向量数据库使用 ANN（近似最近邻）算法，用少量精度损失换取数量级的速度提升。

### 核心 ANN 算法

| 算法 | 原理 | 特点 |
|------|------|------|
| HNSW | 多层跳表图结构 | 查询快，内存占用高 |
| IVF | 先聚类，再在类内搜索 | 内存友好，需要训练 |
| PQ | 向量量化压缩 | 大幅减少内存，精度有损 |
| ScaNN | Google 的各向异性量化 | 高精度，速度快 |

**HNSW** 是最常用的算法：

```
构建: 将向量插入多层图结构
  Layer 2: [A] -------- [D]           (稀疏，长距离连接)
  Layer 1: [A] -- [B] -- [D] -- [E]   (中等密度)
  Layer 0: [A]-[B]-[C]-[D]-[E]-[F]    (密集，短距离连接)

查询: 从顶层开始，逐层向下搜索，越来越精确
```

### 主流向量数据库对比

| 数据库 | 类型 | 索引算法 | 混合检索 | 适用场景 |
|--------|------|---------|---------|---------|
| Pinecone | 云服务 | 自研 | 支持 | 快速上手，免运维 |
| Milvus | 开源 | HNSW/IVF/PQ | 支持 | 大规模生产环境 |
| Qdrant | 开源 | HNSW | 支持 | Rust 实现，性能好 |
| Weaviate | 开源 | HNSW | 支持 | GraphQL API |
| Chroma | 开源 | HNSW | 有限 | 原型开发，轻量 |
| pgvector | PG 扩展 | HNSW/IVFFlat | 天然支持 | 已有 PG 基础设施 |
| FAISS | 库 | 全部 | 不支持 | 研究/嵌入式使用 |

### 选择建议

```
原型开发 → Chroma（几行代码就能跑）
已有 PostgreSQL → pgvector（无需新增组件）
生产环境（中小规模）→ Qdrant 或 Weaviate
生产环境（大规模）→ Milvus
不想运维 → Pinecone
纯研究 → FAISS
```

## 向量数据库的关键特性

### 元数据过滤

不只是向量搜索，还能结合结构化条件：

```
搜索: 语义相似于 "机器学习入门"
过滤: category = "教程" AND language = "中文" AND date > "2024-01-01"
```

先过滤再搜索（pre-filtering）vs 先搜索再过滤（post-filtering），前者更高效但实现更复杂。

### 混合检索

结合向量搜索和全文搜索：

```
向量搜索: 找语义相关的文档
全文搜索 (BM25): 找关键词精确匹配的文档
融合: RRF (Reciprocal Rank Fusion) 合并两个排序列表
```

### 多租户

在同一个数据库中隔离不同用户/组织的数据：

```
Collection: documents
  ├─ Partition: tenant_A (用户 A 的文档)
  ├─ Partition: tenant_B (用户 B 的文档)
  └─ Partition: tenant_C (用户 C 的文档)
```

## 性能优化

### 向量量化

减少存储和加速搜索：

```
原始: float32 × 1536 维 = 6KB/向量
量化: int8 × 1536 维 = 1.5KB/向量 (4x 压缩)
二值化: 1bit × 1536 维 = 192B/向量 (32x 压缩)
```

Matryoshka Embedding（套娃嵌入）允许截断向量维度而不重新训练：

```
1536 维 → 取前 512 维 → 精度损失 <5%，存储减少 3x
```

OpenAI text-embedding-3 系列支持这个特性。

### 索引参数调优

以 HNSW 为例：

| 参数 | 作用 | 权衡 |
|------|------|------|
| M | 每个节点的连接数 | 大 → 更准但更慢、更占内存 |
| ef_construction | 构建时搜索宽度 | 大 → 索引质量更高但构建更慢 |
| ef_search | 查询时搜索宽度 | 大 → 更准但更慢 |

## 实践建议

1. **Embedding 模型选型先看 MTEB 排行榜**：客观对比各模型在不同任务上的表现
2. **先用小模型验证**：BGE-small 验证方案可行后再换大模型
3. **注意最大长度限制**：超出长度的文本会被截断，影响效果
4. **向量归一化**：存入数据库前归一化，使用内积搜索（等价于余弦但更快）
5. **监控召回率**：定期用标注数据评估检索质量

## 小结

Embedding 和向量数据库是 AI 应用落地的基础设施。Embedding 将非结构化数据转化为可计算的向量表示，向量数据库提供高效的相似性检索。选择合适的 Embedding 模型和向量数据库，是构建 RAG、语义搜索等应用的第一步。
