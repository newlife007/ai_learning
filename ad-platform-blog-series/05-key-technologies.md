# 博客五：广告平台关键技术 — 竞价、推荐、反作弊

> 系列文章第 5 篇 / 共 7 篇

## 引言

上一篇我们看了广告平台的整体架构。这篇深入到架构中技术含量最高的三个领域：**竞价机制**（怎么决定展示谁的广告、收多少钱）、**推荐与排序**（怎么预估点击率和转化率）、**反作弊**（怎么识别和过滤虚假流量）。

这三个领域分别对应广告平台的"钱"、"效果"和"信任"。

---

## 1. 竞价机制

### 1.1 为什么需要竞价？

一个广告位在某一时刻只能展示一条广告，但可能有几十甚至上百个广告主都想展示。竞价机制解决的就是**"谁来展示"和"付多少钱"**的问题。

### 1.2 GSP（广义第二价格拍卖）

目前大多数广告平台使用的是 GSP 或其变体。

```
基本 GSP：

3 个广告主竞争 1 个广告位：
  A 出价 10元
  B 出价 7元
  C 出价 4元

结果：
  A 赢得展示
  A 实际付费 = B 的出价 + 最小加价 = 7.01元（而非自己出的 10元）
```

为什么用第二价格而不是第一价格？

```
第一价格拍卖的问题：
  广告主会不断试探"最低能赢的价格"
  → 出价策略变成猜测博弈
  → 市场效率低下

第二价格拍卖的优势：
  广告主的最优策略就是"出自己的真实意愿价"
  → 不需要猜测别人出多少
  → 市场效率更高（激励相容）
```

### 1.3 带质量度的竞价（实际使用的方式）

实际平台不会只看出价，还要考虑广告质量：

```
排序分（eCPM）= 出价 × pCTR × pCVR × 质量因子

其中：
  出价：广告主设定的出价
  pCTR：预估点击率（模型预测）
  pCVR：预估转化率（模型预测）
  质量因子：广告质量评分（落地页体验、历史表现等）

示例：
  广告A：出价 5元(CPC) × pCTR 4% × 质量 1.0 = eCPM 200元
  广告B：出价 8元(CPC) × pCTR 2% × 质量 0.8 = eCPM 128元
  广告C：出价 3元(CPC) × pCTR 5% × 质量 1.2 = eCPM 180元

排序：A(200) > C(180) > B(128)
A 赢得展示，虽然 B 出价最高
```

实际扣费（GSP 变体）：

```
A 的实际 CPC = C 的 eCPM / (A 的 pCTR × A 的质量因子) + 0.01
            = 180 / (4% × 1.0) + 0.01
            = 4500.01元？

等等，这不对。让我用正确的公式：

A 的实际扣费 eCPM = 第二名的 eCPM + 最小增量 = 180.01
A 的实际 CPC = 180.01 / (pCTR × 1000) = 180.01 / (0.04 × 1000) = 4.50元

所以 A 出价 5元，实际只付 4.50元
```

### 1.4 oCPX 下的竞价

在智能出价（oCPX）模式下，竞价逻辑有所不同：

```
广告主设定：目标转化成本 50元/转化

平台内部的竞价过程：
  1. 预估该用户的转化概率 pCVR = 2%
  2. 计算内部出价 = 目标成本 × pCVR = 50 × 2% = 1元/展示（CPM 1000元）
  3. 用这个内部出价参与竞价

对于高转化概率的用户（pCVR = 5%）：
  内部出价 = 50 × 5% = 2.5元/展示 → 出价更高，更容易赢

对于低转化概率的用户（pCVR = 0.1%）：
  内部出价 = 50 × 0.1% = 0.05元/展示 → 出价很低，大概率不展示

这就是 oCPX 的核心：对不同用户动态调整出价
```

### 1.5 VCG 拍卖（理论最优但实践少用）

```
VCG（Vickrey-Clarke-Groves）拍卖：
  每个广告主的付费 = 因为自己的存在，给其他广告主造成的"损失"

优点：激励相容 + 社会福利最大化
缺点：计算复杂，收入通常低于 GSP，实践中很少使用
```

## 2. 推荐与排序模型

CTR/CVR 预估是广告引擎的"大脑"，直接决定了广告效果和平台收入。

### 2.1 问题定义

```
输入：
  用户特征（年龄、兴趣、近期行为...）
  广告特征（行业、创意类型、历史 CTR...）
  上下文特征（时间、设备、网络、当前内容...）

输出：
  pCTR：该用户点击该广告的概率（0~1）
  pCVR：该用户点击后转化的概率（0~1）

要求：
  延迟 < 30ms（单次推理）
  吞吐 > 10万 QPS
  AUC > 0.75（模型质量）
```

### 2.2 模型演进历程

```
第一代：逻辑回归（LR）
  ├── 简单、可解释、推理快
  ├── 需要大量人工特征工程
  └── 无法捕捉复杂的特征交叉

第二代：GBDT + LR
  ├── GBDT 自动做特征交叉
  ├── LR 做最终预测
  └── Facebook 2014 年论文推广了这个方案

第三代：深度学习模型
  ├── Wide & Deep（Google, 2016）
  │   ├── Wide 部分：记忆（LR，捕捉已知的特征组合）
  │   └── Deep 部分：泛化（DNN，发现新的特征组合）
  │
  ├── DeepFM（2017）
  │   ├── FM 层替代 Wide 部分
  │   └── 自动学习二阶特征交叉
  │
  ├── DIN - Deep Interest Network（阿里, 2018）
  │   ├── 引入注意力机制
  │   └── 根据当前广告，动态加权用户历史行为
  │
  ├── DIEN - Deep Interest Evolution Network（阿里, 2019）
  │   ├── 在 DIN 基础上建模兴趣演化过程
  │   └── 用 GRU 捕捉行为序列中的时序关系
  │
  └── 当前主流：多任务学习 + 大模型
      ├── MMOE / PLE：同时预估 CTR 和 CVR
      ├── Transformer-based：用 Transformer 建模行为序列
      └── 预训练 + 微调：用大规模数据预训练通用表示
```

### 2.3 特征工程

特征是模型的"食粮"，特征质量直接决定模型效果。

```
用户侧特征：
  ├── 基础属性：年龄、性别、城市
  ├── 兴趣标签：运动、美妆、数码（长期）
  ├── 近期行为：最近点击的广告 ID 列表、搜索词
  ├── 统计特征：过去 7 天点击率、过去 30 天消费金额
  └── 实时特征：当前 session 的浏览序列

广告侧特征：
  ├── 基础属性：广告主行业、广告类型、创意格式
  ├── 统计特征：历史 CTR、历史 CVR、累计展示量
  ├── 素材特征：图片/视频的 embedding（用 CV 模型提取）
  └── 文本特征：标题/描述的 embedding（用 NLP 模型提取）

上下文特征：
  ├── 时间：小时、星期几、是否节假日
  ├── 设备：手机品牌、操作系统、屏幕尺寸
  ├── 网络：WiFi/4G/5G
  └── 位置：广告在信息流中的位置（第 1 条 vs 第 10 条）

交叉特征：
  ├── 用户年龄 × 广告行业
  ├── 用户城市 × 广告主地域
  └── 用户兴趣 × 广告类别
```

### 2.4 模型训练与部署

```
训练流程：
  1. 样本构建
     正样本：用户点击/转化的 <用户, 广告, 上下文> 三元组
     负样本：用户看到但没点击的三元组
     正负样本比例通常 1:10 ~ 1:100（需要降采样）

  2. 离线训练
     框架：TensorFlow / PyTorch
     数据量：每天数十亿条样本
     训练时间：数小时（分布式训练，多 GPU）
     评估指标：AUC、LogLoss、GAUC（分组 AUC）

  3. 在线 A/B 测试
     新模型上线前，先在小流量（如 5%）上测试
     对比指标：CTR、CVR、RPM（千次展示收入）、广告主 ROI
     显著性检验通过后，逐步放量

部署架构：
  ┌──────────┐    ┌──────────────┐    ┌──────────────┐
  │ 广告引擎  │───▶│  特征服务     │───▶│  模型推理服务  │
  │          │    │ (Feature Store)│   │ (TF Serving) │
  └──────────┘    └──────────────┘    └──────────────┘
                                            │
                                      ┌─────┴─────┐
                                      │ GPU 集群   │
                                      │ 或 CPU 集群 │
                                      └───────────┘
```

### 2.5 冷启动问题

新广告没有历史数据，模型无法准确预估 CTR/CVR。

```
冷启动策略：

1. 探索流量（Exploration）
   给新广告分配一定的"探索预算"
   即使预估不准，也给一些展示机会收集数据

2. 相似广告迁移
   用同行业、同类型广告的历史数据作为先验
   新广告的初始 CTR = 同类广告的平均 CTR

3. 素材特征预估
   用广告素材（图片/视频/文案）的特征来预估
   不依赖历史点击数据

4. 多臂老虎机（MAB）
   Epsilon-Greedy / UCB / Thompson Sampling
   在"利用已知最优"和"探索未知"之间平衡
```

## 3. 反作弊系统

广告作弊是行业痼疾。据估计，全球每年因广告欺诈造成的损失超过 800 亿美元。

### 3.1 常见作弊类型

```
展示作弊：
  ├── 像素填充：把广告塞在 1×1 像素的 iframe 里
  ├── 广告堆叠：多个广告重叠，只有最上面的可见
  ├── 后台展示：App 在后台时仍然上报展示
  └── 机器刷量：用脚本/模拟器批量请求广告

点击作弊：
  ├── 机器点击：脚本自动点击广告
  ├── 点击农场：雇佣真人大量点击
  ├── 点击劫持：用户点击正常内容，实际触发了广告点击
  └── 归因劫持：在用户自然转化前注入虚假点击，抢夺归因

转化作弊：
  ├── 虚假安装：模拟器批量安装 App
  ├── 虚假注册：用虚假信息批量注册
  └── 刷单：虚假购买后退款

流量作弊：
  ├── 设备农场：大量真实设备集中刷量
  ├── 设备 ID 重置：不断重置设备 ID 伪装新用户
  └── VPN/代理：伪造地理位置
```

### 3.2 反作弊技术体系


### 3.3 规则引擎示例

```
规则示例：

规则1：IP 频率限制
  IF 同一 IP 在 1 小时内点击同一广告 > 5 次
  THEN 标记为可疑，后续点击不计费

规则2：点击间隔异常
  IF 两次点击间隔 < 1 秒
  THEN 标记为机器点击

规则3：展示-点击时间异常
  IF 广告展示后 < 0.3 秒就被点击
  THEN 标记为可疑（人类反应时间通常 > 0.5 秒）

规则4：设备异常
  IF 设备 ID 在 24 小时内关联了 > 10 个不同的广告主账户
  THEN 标记为设备农场

规则5：地理位置异常
  IF 用户 GPS 显示在北京，但 IP 地址在越南
  THEN 标记为可疑
```

### 3.4 机器学习反作弊

```
特征工程（用于作弊检测模型）：

设备维度：
  - 设备型号分布（作弊设备型号集中）
  - 操作系统版本分布
  - 是否 root/越狱
  - 传感器数据是否正常（加速度计、陀螺仪）

行为维度：
  - 点击位置分布（真人有热区，机器均匀分布）
  - 点击时间分布（真人有昼夜规律，机器 24 小时均匀）
  - 会话时长分布
  - 页面浏览深度

网络维度：
  - IP 地址信誉度
  - 是否使用代理/VPN
  - 同一 IP 下的设备数量

关联维度：
  - 设备-IP-账户的关联图谱
  - 异常聚集的设备群（图聚类）
```

### 3.5 归因反作弊

```
归因劫持（Attribution Fraud）是最隐蔽的作弊方式：

正常流程：
  用户看到广告 → 点击 → 安装 App → 归因给该广告

归因劫持：
  用户自然搜索 → 准备安装 App
  → 作弊方在安装前一刻注入一个虚假点击
  → 安装完成后，归因系统认为是这个"点击"带来的安装
  → 作弊方获得 CPA 收入

防御手段：
  - CTIT（Click-To-Install Time）分析
    正常安装：点击后 30秒-24小时 安装
    归因劫持：点击后 < 10秒 就安装（不合理）
  
  - 点击分布分析
    正常渠道：点击量和安装量有合理比例
    作弊渠道：大量点击但安装率异常高
```

## 4. 预算控制算法（Pacing）

### 4.1 问题定义

```
广告主设定：日预算 10,000 元

如果不控制：
  上午流量高峰期，预算可能 2 小时就花完了
  下午和晚上的优质流量就错过了

目标：
  在一天内均匀消耗预算，同时最大化转化效果
```

### 4.2 Pacing 算法

```
方法一：概率节流（Throttling）

  计算当前消耗进度 vs 时间进度：
    消耗进度 = 已花费 / 日预算
    时间进度 = 已过时间 / 24小时

  IF 消耗进度 > 时间进度 × 1.1（超前消耗）
    THEN 降低参与竞价的概率（如从 100% 降到 50%）
  
  IF 消耗进度 < 时间进度 × 0.9（消耗不足）
    THEN 提高参与竞价的概率（如从 50% 提到 100%）

方法二：出价调整（Bid Modification）

  不改变参与率，而是调整出价：
    超前消耗 → 降低出价系数（如 ×0.8）
    消耗不足 → 提高出价系数（如 ×1.2）

方法三：PID 控制器

  用 PID（比例-积分-微分）控制器来调节：
    误差 = 目标消耗速率 - 实际消耗速率
    调整量 = Kp × 误差 + Ki × 累积误差 + Kd × 误差变化率
    
  这是工业控制中的经典方法，在预算控制中效果很好
```

## 5. 创意优选

一个广告计划下可能有多条创意（不同的视频/图片/文案），平台需要自动选出效果最好的。

### 5.1 多臂老虎机（MAB）

```
问题建模：
  N 条创意 = N 台老虎机
  每次展示 = 拉一次老虎机
  点击/转化 = 获得奖励
  目标：最大化总奖励

常用算法：

1. Epsilon-Greedy
   以 ε 的概率随机探索，以 1-ε 的概率选择当前最优
   简单但不够高效

2. UCB（Upper Confidence Bound）
   选择 "平均奖励 + 不确定性奖励" 最高的创意
   score = avg_reward + sqrt(2 × ln(N) / n_i)
   展示越少的创意，不确定性越大，越有机会被探索

3. Thompson Sampling
   为每条创意维护一个 Beta 分布
   每次从分布中采样，选择采样值最高的创意
   自然地平衡探索与利用
```

### 5.2 动态创意优化（DCO）

```
传统方式：广告主上传 3 条完整创意，平台选最优

DCO 方式：
  广告主上传：
    标题：["限时特惠", "新品首发", "爆款推荐"]
    图片：[图A, 图B, 图C]
    描述：["立即购买", "了解更多", "免费试用"]
    CTA按钮：["立即下载", "马上抢购"]

  平台自动组合：3 × 3 × 3 × 2 = 54 种创意组合
  通过 MAB 算法自动找到最优组合
  不同用户可能看到不同的组合（千人千面）
```

## 6. 实时数据处理

### 6.1 事件上报与处理

```
事件类型与处理流程：

展示事件（Impression）
  → SDK 上报 → Kafka → Flink 实时处理
  → 更新：展示计数、频次计数、预算消耗
  → 延迟要求：秒级

点击事件（Click）
  → SDK 上报 → Kafka → Flink 实时处理
  → 更新：点击计数、计费扣款
  → 触发：反作弊实时检测
  → 延迟要求：秒级

转化事件（Conversion）
  → 广告主服务器回传 / SDK 上报
  → 更新：转化计数、ROI 计算
  → 用于：模型训练样本、oCPX 出价校准
  → 延迟要求：分钟级（转化可能有延迟）
```

### 6.2 实时特征更新

```
用户实时行为 → Kafka → Flink → 更新 Redis 中的实时特征

示例：
  用户 10:00 搜索了"跑步鞋"
  → 10:00:01 实时特征更新：recent_search = ["跑步鞋"]
  → 10:00:05 用户刷信息流，广告引擎读取最新特征
  → 展示跑步鞋相关广告

这就是为什么你搜完一个东西，马上就能在信息流里看到相关广告
```

## 7. 技术挑战总结

| 技术领域 | 核心挑战 | 关键指标 |
|----------|---------|---------|
| 竞价机制 | 激励相容、收入最大化 | 平台 RPM、广告主 ROI |
| CTR/CVR 预估 | 准确性、实时性、冷启动 | AUC > 0.75、延迟 < 30ms |
| 反作弊 | 对抗性强、手段不断升级 | 作弊识别率 > 95%、误杀率 < 1% |
| 预算控制 | 均匀消耗、效果最大化 | 预算消耗偏差 < 5% |
| 创意优选 | 探索与利用的平衡 | 收敛速度、最优创意命中率 |
| 实时数据 | 高吞吐、低延迟 | 百万级 TPS、秒级延迟 |

## 小结

广告平台的关键技术可以归纳为：

1. **竞价**：GSP + 质量度，在 oCPX 模式下由平台动态出价
2. **推荐排序**：从 LR 到深度学习，CTR/CVR 预估是核心，特征工程是基础
3. **反作弊**：规则 + 模型 + 图分析，事前防御 + 事中检测 + 事后追溯
4. **预算控制**：PID 控制器 / 概率节流，保证预算均匀消耗
5. **创意优选**：MAB 算法（Thompson Sampling），自动找到最优创意
6. **实时处理**：Kafka + Flink，秒级更新特征和计费

这些技术共同支撑了广告平台每天数百亿次的广告决策。下一篇，我们从实战角度看看如何对接广告平台的 API。
